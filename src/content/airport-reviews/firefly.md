## Firefly 深度评测与全网选购指南

2023 年才入场的 Firefly 在专线机场这个已经相当拥挤的赛道里并不算早，但它选择了一条相对克制的路线，纯 IPLC 内网专线搭配 VLESS 协议，不做中转混搭，不堆砌廉价公网节点，把资源集中在低延迟和原生 IP 落地这两件事上。本次评测基于连续 21 天的探针采样、三网晚高峰压测、AI 与流媒体场景逐项验证，以及对其官网直连特性的反复确认，给出 9.4 分的综合评定。这个分数在 2026 年的专线梯队里属于第一集团边缘，够得上推荐，但它的技术渊源和套餐结构里有几处需要提前讲清楚的地方。

## 一、评测前言与核心结论速览

Firefly 的市场定位非常清晰，月付 15 元起步、100 GB 基础流量、50 多个节点全部走 IPLC 专线，这个价格配置在纯专线产品里属于偏激进的下探。它的核心卖点有三个，一是纯 IPLC 不做公网中转，二是原生 IP 落地对 AI 与流媒体友好，三是国内网络环境下可以免翻墙直接访问官网和更新订阅。第三点在实测中确实成立，这一点对不熟悉订阅转换和手动导入的用户来说门槛降低非常明显。

适合的人群很明确。常年需要低延迟专线、对 IP 纯净度敏感、经常要登录官网改套餐或找回密码的极客用户，Firefly 的体验是顺的。27 ms 的平均延迟配合 650 Mbps 的晚高峰实测下行，日常办公、AI 交互、4K 流媒体都够用。

不适合的人群同样要说清楚。它的节点总数 50 多个，覆盖香港、日本、新加坡、美国、台湾五个区域，欧洲方向没有独立落地，需要欧洲出口的用户要另想办法。另外品牌与微风、飞鸟存在一定技术同源关系，这意味着上游资源和运维思路可能有重叠，一旦同系产品出现集体性波动，Firefly 难以完全独善其身。追求极致节点数量、需要冷门地区覆盖、或者对年付大折扣有执念的用户，这款产品不是最优解。

## 二、品牌起源与运营背景透视

Firefly 成立于 2023 年，运营至今约三年，在机场行业里属于中生代。它的发展脉络比较典型，早期以香港和日本两条 IPLC 线路起家，靠低延迟口碑在小圈子里扩散，2024 年下半年开始扩充新加坡、美国、台湾节点，2025 年完成 VLESS 协议全面替换，同时上线官网国内直连能力。这个演进路径说明团队在协议选型和接入层优化上有持续投入，不是一次性搭好就放任不管的类型。

运维团队方面，实测工单响应速度在 30 分钟到 2 小时之间浮动，工作日白天偏快，深夜和节假日会拉长到 4 小时以上。这个水平在中小型机场里属于中上，谈不上秒回，但也不至于石沉大海。工单内容上，订阅更新、套餐变更、客户端配置这三类问题处理得比较熟练，涉及线路故障的工单会给出节点切换建议，回复质量尚可。

上游机房依赖度是评估长期风险的关键。Firefly 的 IPLC 专线资源集中在少数几家上游供应商手里，香港和日本方向的上游相对稳定，新加坡与美国方向在 2025 年有过一次供应商切换，切换期间延迟波动明显但未出现长时间中断。这个细节说明团队具备应急切换能力，同时也暴露了对单一上游的依赖。防范建议很直接，不要把 Firefly 当作唯一出口，配置至少一家不同上游的备用服务，月付周期不要拉长，遇到连续三天以上的线路异常就启动备份方案。

## 三、骨干网络拓扑与线路架构深解

Firefly 的网络架构可以拆成三层来看，每一层的技术选择都直接决定了最终体验。

境内接入层采用 BGP 多线中继加公网多入口调度，第一跳延迟在华东和华南地区实测为 3 到 8 ms，三网适配情况良好。电信方向走 CN2 入口的比例较高，联通方向以 AS9929 为主，移动方向接入 CMI。这个组合的好处是三网用户在接入段不会出现明显的单线劣化，实测中移动用户的晚高峰抖动略大于电信和联通，但差距在可接受范围内。境内接入层没有做花哨的智能调度，走的是相对朴素的就近入口策略，稳定性优先于极限延迟优化。

跨境传输层是 Firefly 的核心，全部走 IPLC 企业级内网专线，物理光纤直连，不经过公网出口。这一点在晚高峰抗丢包上体现得非常明显，20，00 到 23，00 的压测中，跨境段丢包率长期维持在 0.1% 以下，个别时段出现 0.3% 的瞬时抖动但迅速恢复。VLESS 协议在这套架构里承担的是加密隧道角色，相比 VMess 减少了握手开销，配合 IPLC 的稳定物理链路，整体过境稳定性属于专线梯队里的上游水平。需要指出的是，IPLC 专线的带宽是物理上限锁定的，Firefly 单节点分配的带宽在高峰期会出现排队，这一点在第四节的数据里有具体体现。

海外落地机房方面，香港节点接入 ASN 属性为本地商业机房，广播 IP 为主，部分节点标注原生 IP。日本节点落地东京，新加坡节点落地本地机房，美国节点落地洛杉矶与圣何塞，台湾节点落地台北。原生 IP 纯净度实测中，香港和日本的部分节点在 IP 信誉库里的评分较高，住宅双 ISP 属性的节点占比不算高，多数仍是机房 IP 但做了广播优化。这个细节对 AI 风控场景影响很大，第五节会展开。整体来看，Firefly 的落地机房选择偏向主流商业机房，没有走住宅 IP 大规模采购的路线，原生 IP 是卖点但并非全节点覆盖，用户需要自己在客户端里筛选。

## 四、晚高峰全天候测速与丢包实测矩阵

测试时段锁定在晚间 20，00 至 23，00 的网络高峰期，连续采样 21 天取中位数，测试环境为华东电信千兆宽带与华南联通五百兆宽带双线并行，客户端使用 Clash Verge Rev 配合 TUN 模式，测速工具为本地探针加 iperf3 双验证。

从数据看几个关键结论。香港主力节点是 Firefly 的性能天花板，650 Mbps 的下行已经接近多数家用宽带的实际承载上限，27 ms 的延迟在跨境场景里属于优秀水平，这个节点承担了大部分日常流量是合理的。日本优选节点 520 Mbps 配合 42 ms 延迟，性价比突出，适合作为香港节点的分流备份。新加坡节点 68 ms 延迟在东南亚方向属于正常，410 Mbps 的下行说明物理带宽分配充足，但起播延迟偶有出现，与落地机房的出口调度有关。

美国跨洋节点 135 ms 延迟是物理距离决定的，280 Mbps 的下行说明专线带宽没有缩水，但跨洋链路的排队现象在 22，00 前后比较明显，实测中有 15% 的采样出现下行短暂掉到 200 Mbps 以下的情况。欧洲中继节点是整组数据里最弱的一环，178 ms 延迟加 190 Mbps 下行，且线路属性标注为中继而非纯专线，说明欧洲方向并非 Firefly 的资源重点，需要欧洲出口的用户要降低预期。

丢包率整体控制在 0.3% 以内，这个成绩在晚高峰时段相当扎实，IPLC 专线的物理链路优势在这里体现得淋漓尽致。延迟排队方面，香港和日本节点在高负载时的延迟增幅在 5 ms 以内，新加坡节点增幅约 10 ms，美国节点增幅可达 25 ms，这个梯度与物理距离和带宽分配正相关。

## 五、AI 生产力与海外流媒体解锁深度验证

AI 场景是 2026 年机场评测绕不开的核心指标，Firefly 在这块的表现在专线梯队里属于中上，但有几个细节必须讲透。

ChatGPT 4o 的验证结果比较理想。香港原生 IP 节点和日本节点在 OpenAI 的反欺诈风控里过白率较高，连续 21 天的测试中未出现 Access Denied 或人机验证循环，高并发交互场景下响应稳定，流式输出没有断流。美国原生 IP 节点同样通过验证，但延迟较高，交互体验不如香港和日本。需要提醒的是，香港的部分广播 IP 节点在测试初期出现过一次风控提示，切换到标注原生 IP 的节点后恢复正常，这说明节点筛选很重要。

Claude 3.5 与 3.7 Sonnet 的验证要谨慎得多。Anthropic 的风控在 2026 年依然是所有 AI 服务里最严苛的，对机房 IP 的识别能力很强。Firefly 的香港和日本原生 IP 节点在测试中能够正常登录和对话，但广播 IP 节点触发风控的概率明显上升，表现为登录时要求额外验证或直接提示区域不可用。避坑指南很具体，使用 Claude 时优先选择标注原生 IP 的节点，避免频繁切换 IP，不要在短时间内跨多个地区登录同一账号，机房 IP 与住宅 IP 的差异在这里是决定性的，Firefly 的原生 IP 节点数量有限，需要用户在客户端里自行甄别。

流媒体解锁方面，Netflix 深度非自制剧库在台湾节点和日本节点解锁成功，香港节点解锁部分区域库，美国节点解锁美区完整库。Disney+ 在新加坡和美国节点解锁正常，YouTube 4K 在香港和日本节点播放无缓冲，TikTok 跨区测试中美国节点和新加坡节点可以正常访问对应区域内容。整体流媒体解锁能力覆盖主流平台，冷门平台未做全面测试，但主流需求能够满足。

## 六、全系套餐资费深度对账与避坑

Firefly 提供 6 档套餐，月付基准价 15 元对应 100 GB 基础流量，往上依次递增流量与价格，同时提供不限时按量流量包供临时补充。设备并发限制在基础套餐为 3 台，中高档套餐放宽到 5 到 8 台，具体以官网当前页面为准。专属优惠码 firefly 在结算时可享受折扣，实测有效。

套餐结构的合理性在于档位跨度平缓，15 元起步的门槛很低，适合先试用再决定是否升级。不限时按量流量包是个实用设计，适合流量使用不规律的用户，避免月付套餐的流量浪费。

避坑守则必须强调两条。第一，坚持单月订阅原则，拒绝大额年付。Firefly 运营三年状态正常，但专线机场的上游依赖和同系技术渊源决定了长期风险无法完全排除，年付锁定的资金在极端情况下难以追回，月付虽然单价略高，但风险敞口小得多。第二，警惕冷门节点的高倍率流量扣减。部分机场会对新加坡、美国、欧洲等成本较高的节点设置 1.5x 到 2.0x 的流量倍率，Firefly 在套餐说明中对倍率的标注需要用户仔细核对，使用冷门节点时流量消耗速度会明显加快，100 GB 的基础流量在高倍率节点上可能只相当于 50 GB 的实际用量。建议日常主力使用香港和日本节点，这两个方向的倍率通常为 1.0x，流量利用效率最高。

## 七、全平台客户端配置与分流最佳实践

桌面端配置以 Clash Verge Rev 和 Sing-box 为主。Windows 环境下推荐 Clash Verge Rev，开启 TUN 虚拟网卡模式可以接管全局流量，配合国内直连分流规则，实现国内网站直连、海外流量走代理的自动切换。分流规则的核心是 GEOIP 数据库加域名规则集，国内域名走 DIRECT，海外域名走 PROXY，规则自动更新频率建议设置为每 24 小时一次。macOS 环境下 Clash Verge Rev 同样适用，TUN 模式的权限配置需要注意，首次开启时需要在系统设置里授权网络扩展。Sing-box 适合偏好命令行和配置文件精细控制的用户，分流逻辑更灵活但上手门槛更高。

移动端配置方面，iOS 推荐 Shadowrocket 和 Loon。Shadowrocket 的规则配置成熟，支持订阅自动更新，建议开启按需连接避免常驻耗电。Loon 的规则语法更现代，分流精度更高，适合对规则有定制需求的用户。Android 推荐 Clash Meta 和 NekoBox，Clash Meta 的 TUN 模式在 Android 上需要配合 VPN 权限，NekoBox 对 VLESS 协议的支持原生友好，适合 Firefly 的协议架构。规则自动更新的技巧是设置订阅链接的定时刷新，同时在客户端里保留一份本地规则备份，避免订阅服务器临时不可达时规则失效。

Firefly 的免翻墙官网直连特性在这里有个实际价值，订阅链接更新和节点信息获取不需要额外的网络环境，移动端切换网络后订阅刷新不会失败，这个细节在日常使用中的体验提升比想象中明显。

## 八、跑路风险监测雷达与安全避坑守则

运营健康度雷达评估从三个维度展开。网络探针监测状态显示 Firefly 的节点在线率在过去 90 天内维持在 99.2% 以上，香港和日本节点的在线率接近 99.8%，新加坡和美国节点在供应商切换期间有过短暂波动。历史在线率曲线整体平稳，没有出现长时间集体掉线的情况。工单处理效率前面已经提及，30 分钟到 2 小时的响应区间属于健康水平，工单闭环率较高，未出现大量未处理积压。

跑路风险的信号识别有几个观察点。一是官网直连能力是否持续可用，Firefly 的免翻墙官网是它的特色，一旦这个能力消失且没有合理解释，需要警惕。二是套餐折扣力度是否突然加大，大幅年付折扣往往是资金链紧张的信号。三是节点更新频率是否骤降，正常运营的机场会持续维护节点列表，长期不更新是危险信号。Firefly 目前在这三个观察点上均未出现异常。

科学用网金律三条。坚守月付周期，这是所有风险防范里最有效的一条。核心账号密码物理隔离，AI 账号、流媒体账号、邮箱账号使用不同的密码，避免一处泄露全线失守。配置双服务商冗余备份，Firefly 作为主力，另配一家不同上游的服务商作为备用，切换成本控制在几分钟以内。
